# 숏폼 키워드와 AI 타깃 추천

## When to Use
뉴스에서 소재 키워드를 추출하고 AI가 연령·성별 기획 타깃을 추천하는 브리핑을 만든다. 기본 흐름은 뉴스 수집 → 키워드 추출 → AI 타깃 추천 → 브리핑이다. 데이터랩은 사용하지 않는다. 실제 전송·정기 실행은 별도 승인 범위다.

## Procedure
1. 프로젝트 코드를 다룰 때는 `read_file`로 AGENTS.md·README·설계를 읽고 `terminal`로 git status와 현재 브랜치를 확인한다. 승인 없이 커밋·업로드하지 않는다. 스킬 수정과 코드 구현을 구분한다.
2. 실제 수집 JSON의 수량·수집시각·검색기간·조회상한을 코드로 검증한다. 실패·빈 결과·과거 수집본을 구분하고 최대 30일 입력기간을 검사한다. 뉴스 API 인증이 없으면 새로 수집했다고 말하지 않는다. 기존 자료를 쓰면 원래 수집시각을 표시한다.
3. 네이버 pubDate는 제공시각으로 표시하고 원문 게시일과 구분한다. 제목에 직접 숏폼 관련성이 있는 기사와 본문 검색에만 걸린 기사를 구분한다. 일반 소재 키워드도 활용할 수 있지만 기사 자체가 숏폼 관련 기사라고 바꿔 쓰지 않는다.
4. 실제 제목·확인한 요약 또는 본문에서 구체적인 소재·현상·형식 키워드를 추출하고 중복을 정리한다. 읽지 않은 본문을 읽었다고 하지 않는다. 키워드마다 원문 표현과 출처 링크를 보존한다. 바이트댄스를 댄스로, 인플루언서라는 단어만으로 커머스로 분류하지 않는다.
5. 기본 추천 대상은 출처가 명확한 중복 제거 후보 최대 30개다. 전체 후보와 선정·제외 목록을 보존하고 선정 기준·분석 범위를 표시한다. 분야·집단마다 30개씩 채우지 않고 후보가 적으면 임의로 늘리지 않는다. 전체 목록을 요청하면 아래 목록 모드를 따른다.
6. 각 키워드의 소재 맥락·사용 상황·생애 단계·설명 난이도·콘텐츠 형식을 읽고 AI가 타깃을 직접 추천한다. 연령별 조사 자료나 추가 분석 API를 필수 조건으로 요구하지 않는다. 기사 인물의 나이·2030년 같은 숫자를 시청자 선호 근거로 쓰지 않는다.
7. 상단에 반드시 'AI의 기획 추천이며 실제 선호 통계가 아님'을 표시한다. 뉴스에 실제로 있는 사실과 AI가 제안한 타깃·활용 가설을 분리한다. 언급량을 인기·상승세·타깃의 실제 선호로 표현하거나 측정하지 않은 점수·확률을 만들지 않는다.
8. 기본 출력은 아래 간단한 형식을 따른다. 길면 메시지를 나누고 선정한 키워드나 출처를 조용히 생략하지 않는다.
9. 테스트와 실제 입력 기반 생성 후 수량·출처·추천 표시·메시지 길이를 검증한다. HTML 미리보기가 있으면 브라우저에서 데스크톱·모바일을 확인하고 사용자에게 직접 확인을 요청한다. 사용자 확인 전 커밋하지 않는다.

## AI 타깃 추천 기준과 출력
- 기본 연령 구간은 10대·20대·30대·40대·50대 이상이다. 필요하면 여러 구간 또는 더 구체적인 범위를 추천하고, 구분할 이유가 없으면 '전 연령'으로 둔다. 사용자 지정 구간을 우선한다.
- 성별은 남성·여성·성별 공통으로 표시한다. 차이를 제안할 맥락이 없으면 '성별 공통'을 기본으로 둔다. 뷰티는 여성·금융은 남성처럼 고정관념만으로 배타적으로 배정하지 않는다. 특정 집단 추천은 다른 집단이 관심 없다는 뜻이 아니다.
- 키워드마다 추천 타깃과 짧은 판단 이유를 남긴다. 하나의 키워드를 여러 집단에 추천할 수 있다. 맥락이 부족하면 '판단 보류'와 이유를 남긴다. 결과를 근거 부족만으로 채우지 말고 가능한 기획 제안을 하되 불확실성을 숨기지 않는다.
- 기본 형식: 안내 문구 → 자료 수집시각·분석 범위 → 키워드별 추천 → 출처·한계 → 연령대별 키워드 요약표.
- 결과 맨 마지막에 '연령대 | 키워드' 2열 요약표를 붙인다. 10대·20대·30대·40대·50대 이상 각 행에는 기존 추천에 해당하는 키워드만 콤마로 나열하고 이유·기사 제목·출처는 반복하지 않는다. 여러 연령에 추천한 키워드는 각 행에 표시하며 행 내 중복은 제거한다. 전 연령 추천은 모든 연령 행에 포함하고, 판단 보류는 별도로 표시한다. HTML은 실제 table로, 일반텍스트는 같은 내용의 간단한 행으로 제공한다. 표에도 AI 기획 추천임을 표시하고 기존 추천과의 일치·누락 여부를 검증한다.
- 키워드별 형식: '키워드 / 추천 연령 / 추천 성별 / 판단 이유 한 줄 / 출처'. 판단 이유는 기획 가설이지 조사 결과가 아니다.
- 사용자가 통계 검증을 별도로 요청하면 국내 직접조사기관 원문에서 명시 연령·관심 주제·공개일·조사 기간·표본 범위를 확인하고 추천과 분리한다. 자료가 없으면 검증되지 않았다고 표시한다. 기본 추천을 위해 이 절차를 의무화하지 않는다.

## 폭넓은 키워드 목록 모드
- 전체 목록을 요청하면 기본 최대 30개 제한을 해제하고 전체, 연령별, 성별, 연령·성별 공통, 판단 보류 순서로 쉼표 목록을 표시한다. TOP N으로 몰래 줄이지 않는다. 각 집단 구분은 AI 기획 추천임을 표시한다.
- 큰 주제명으로 세부 소재·현상·형식 표현을 지우지 않는다. 실제 자료에 있는 표현만 추출하고 모든 출처 위치를 보관한다. 동의어는 명시적이고 확인 가능한 매핑으로만 통합한다.
- 여러 배치를 분석하면 모든 입력 기사 ID의 처리 여부와 근거 표현의 원문 포함 여부를 코드로 검증한다. 실패·미처리 배치를 조용히 제외하지 않는다. AI 사용량 제한에 걸리면 처리한 범위와 미처리 범위를 표시한다.
- 분류별 개수는 집합으로 계산한다. 중복 배정은 허용하되 전체 고유 수는 한 번만 센다. 근거 기사 번호와 키워드별 참조를 전부 보존한다.
- 길이 초과는 메시지 수를 늘려 해결한다. 전체 미리보기와 메시지 배열의 무손실 동일성을 검사한다.

## Pitfalls
- 데이터랩 호출·연령 코드별 20개 집단 조회·14일 검색 지수 비교·상승률 기준·데이터랩 호출 예산·전용 캐시는 범위에서 제외한다. 뉴스 API와 AI 처리의 사용량·오류는 별도로 남는다.
- 같은 입력의 기존 결과가 있으면 재전달에 활용하고 재분석 여부·원래 분석시각을 밝힌다. 정기 실행이나 복잡한 캐시 체계를 이 스킬 수정만으로 추가하지 않는다.
- 수동 검증 플래그는 프로그램이 출처 진위를 자동 인증했다는 뜻이 아니다. 합성 테스트나 출력 예시를 실제 수집·분석 결과로 보여주지 않는다.
- 키를 코드·커밋·로그에 넣지 않는다. 출력은 gitignore된 로컬 폴더에 보관한다. 실제 전송·정기 실행은 승인 없이 켜지 않는다.
- 일반텍스트는 UTF-16 코드 단위 3500 이하로 나눈다. 인라인 URL을 통째로 보존하고 너무 긴 URL은 자르지 말고 명시적으로 실패시킨다. HTML은 이스케이프하고 http(s) 링크만 생성한다.

## Verification
- 실제 입력 수량과 처리·미처리 수량, 후보의 중복 제거 및 기본 최대 30개 제한 또는 명시적인 전체 목록 요청을 확인한다.
- 모든 추천 키워드에 원문 표현·출처·추천 연령·추천 성별·판단 이유 또는 보류 이유가 있는지 확인한다. 안내 문구가 있고 측정하지 않은 인기·상승률·선호 확률을 주장하지 않는지 점검한다.
- 데이터랩 호출이 없는지 확인한다. 코드가 과거 통계 모드만 구현했다면 AI 추천 모드까지 구현·검증됐다고 말하지 않는다.
- 파일과 메시지 배열의 동일성, 합계, 원본 출처 URL, 개별 메시지 길이, HTML 브라우저 표시를 도구로 확인한다. 실제 수집·AI 분류·전송 중 수행하지 못한 부분을 최종 답변에 명시한다.
